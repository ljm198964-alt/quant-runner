## Line-specific probability and outcome diagnostic

Using the saved D1 2026/27 walk-forward fit parameters and the archived Crown line in memory, the three fitted goal distributions were reconstructed. Their AH and OU probabilities agree with the saved OOS row's relevant goal-distribution probabilities to less than `1e-9` for the checked outcomes. The table reports probabilities for the archived line, not a general AH/OU metric:

EV is probability × Crown decimal odds − 1 for these single-outcome lines. It uses the displayed line-specific probabilities (rounded to 6 decimals); all 12 model × market × side estimates are negative. This is one retrospective quote, not a strategy return or evidence of an edge. At a counterfactual 1-unit stake, the settled side outcomes are AH home −1.00 / away +0.95 units, and OU over +1.04 / under −1.00 units. No side-selection policy was preregistered; these four side outcomes are separate diagnostics and must not be summed into PnL. Strategy ROI, cumulative return and maximum drawdown therefore remain unavailable. Daily/weekly, season and league subgroups each have n=1 or no samples and are not statistically meaningful. The V4 original target is O2.5, so its five variants have no supported evaluation on this 3.5 goal line.

The existing [`probabilities.py`](probabilities.py) already calculated Asian settlement states across score grids. Its public API now also settles an exact final score for AH/OU and computes unit EV from full/half settlement-state probabilities, avoiding a second implementation. It supports quarter lines and does not fetch quotes, define a side-selection policy, or certify bookmaker provenance. Synthetic and observed-score calculation coverage is in `test_probabilities.py`.

For this one recorded price pair per market, all 12 model × market × side theoretical unit-EV calculations were negative. That retrospective diagnostic is highly sample-limited and is not an ROI estimate. With the verified 2–2 final score, the selected AH home side lost and away side won; OU over won and under lost. No side-selection policy was fixed in advance and no bet was placed, so there is no valid realized PnL, ROI, or maximum drawdown sequence. The winning-side outcomes do not turn ex-ante negative EV into positive expected value.

AH and OU are reported separately. The result does not show whether either model is profitable over a sample. It only demonstrates that saved M3 parameters can be reconciled with one archived Crown-labelled line without using a post-kickoff quote.

## Coverage gap and next step

The archived artifact cannot supply a denominator-wide Crown historical panel. No conclusion about absence of Crown data elsewhere is warranted. The single M3 intersection is a retrospectively generated strict-walk-forward hindcast; there are zero matches in this artifact with a contemporaneously timestamped M3 forecast followed by a Crown quote. M3 has not obtained an authorized, sufficiently broad, contemporaneous Crown archive, so Crown line-level OOS Log Loss/Brier, valid-strategy yield, ROI and drawdown remain unavailable. The no-market OOS and shadow results remain the broader model evidence; the shadow ledger has 4,215 unique forward forecast keys but zero settlements and no captured Crown quotes.

TotalCorner's current terms prohibit automated extraction without prior written consent ([Terms](https://www.totalcorner.com/page/terms)); its API documentation's historical movement endpoint does not itself establish data collection or redistribution permission ([API](https://www.totalcorner.com/page/api)). The accompanying [offline M3 Crown evidence intake contract](crown_evidence_contract.md) provides structural and UTC validation for separately authorized, operator-supplied evidence. It does not fetch, publish restricted prices, compute ROI or create a trading gate.

### Official API schema and offline intake readiness (2026-10-20)

The current TotalCorner API specification describes `/match/bookmaker_odds/{match_id}`, `bookmaker=crown`, full-time AH and goal-line markets, and optional `asianList` / `goalList` movement arrays. A movement row carries the line, both prices, source-local timestamp, score and closed flag; the API documentation says names/timestamps follow the account profile timezone. The same page says API access requires VIP membership. Separately, the current Terms page (last updated 2026-09-02) prohibits automated data extraction without prior written consent. Therefore an API token or paid membership is not accepted by M3 as a substitute for written collection/use/retention permission. No API call was made in this audit.

An offline adapter, `crown_totalcorner_import.py`, now maps an already-authorized raw response into the private evidence validator's schema. It requires written-permission metadata first, exact source match ID and team identities, evidence for the account IANA timezone, exact independent UTC kickoff agreement, unique Crown bookmaker entry, open pre-match rows only, and valid M3 forecast/hindcast provenance. DST gaps/folds, compound comma-form lines, ambiguous mapping, suspended rows and all rows at/after kickoff fail closed or are excluded. Raw quote values are never printed or committed by the CLI; input retention remains subject to authorization. Unit tests use synthetic fixtures and do not establish real data coverage.

This makes the legal-data intake path implementable after permission is supplied; it does not change any Stage A coverage count. Broad historical Crown AH/OU overlap with M3 forecasts, Crown-specific OOS metrics, EV, PnL, ROI and drawdown remain unavailable.

The official [TotalCorner API documentation](https://www.totalcorner.com/page/api) describes date and league schedule endpoints, an explicit `bookmaker=crown` endpoint, example `curl`/Python requests, VIP-based API access, and a 30-request-per-minute limit. It identifies Crown AH and goal-line markets and states that account profile settings control names and timestamps. Those details establish that an official programmatic Crown interface exists and is designed to be called by API clients. The [current Terms of Service](https://www.totalcorner.com/page/terms), however, define the Service to include APIs and separately prohibit automated extraction without prior written consent; they do not expressly say whether documented API calls are exempt, nor do they grant a public right to retain or redistribute Crown quote values. Thus the public materials do not settle the scope of any existing account/API authorization for unattended M3 collection and publication. This is distinct from whether the endpoint exists or has been used before.

An M3-only fixture-ID discovery and pairing pipeline is technically possible without importing M1/MR1 identities or forecasts. Current M3 forward forecasts use OpenFootball calendar dates with no documented time zone; that schedule alone is insufficient for exact kickoff/time joins. An independently documented UTC kickoff and exact team identity must be established before pairing a Crown quote. The only M3-linked historical archive remains one fixture with pre-kickoff quotes and retrospective hindcast probabilities, not a contemporaneously recorded forecast; no Crown ROI is estimable.

**Forward-capture status: not started.** The repository credential is available by name, but the public project files contain no traceable permission reference for unattended M3 retrieval, quote retention, or public release. The official API docs show the endpoint and intended client usage; the Terms of Service leave the relationship between that API access and the broad automated-extraction clause unclear. These sources do not prove that the existing authorization covers this workflow or publication. This is an evidence gap, not a request for a new token. Existing credentialed M1/MR1 use cannot be repurposed as M3 data or taken as proof of M3 permission. Until an already-existing permission scope can be substantiated in authorized project records, do not start a new M3 endpoint call, retain new raw market values in public Actions artifacts, or represent the collector as active.
